Exam scope & format

One paper, 100 marks, 3 hours (180 minutes), covering all content from Semester 2 (Blocks 3 and 4). It follows the layout of Test 1 and Test 2: a multiple-choice section, a scenario section applying interaction design, and a large case-scenario section built from systems design, database design and ADO.NET.

Section A — Multiple Choice Questions15 MARKS

30 questions at ½ mark each · Block 3 and Block 4 content · suggested time: about 40 minutes

These MCQs test reasoning and analytical skills, not recall. Expect to diagnose a flawed design, trace a short piece of code, apply a rule to a table or diagram, and pick the best of several plausible options. The content below is spread across all four practice papers, because it cannot all fit into one 30-question paper.

  1. Relational data model and integrity rules (Block 3)
    • Entity integrity: every table has a primary key, and its values must be unique and NOT NULL.
    • Referential integrity: a foreign key value must match an existing primary key value, or be NULL where the column allows it (for example a project with no manager assigned yet).
    • Key types: primary key (a composite key when several attributes are combined), foreign key, surrogate key (an artificial sequential number when no natural key exists), superkey (any attribute set that uniquely identifies a row) and candidate key (a minimal superkey that could become the primary key).
    • Controlled redundancy: foreign key values are deliberately duplicated to link tables. Indexes speed up lookups.
  2. Normalisation and anomalies (Block 3)
    • Anomalies: insertion (cannot record one fact without another), update (a duplicated value changed in one row only) and deletion (deleting a row loses an unrelated fact).
    • 1NF: atomic values (no repeating or multivalued cells), a defined primary key, no dependence on row order, and one data type per column.
    • 2NF: in 1NF with no partial dependencies on part of a composite key. A table with a single-column primary key is automatically in 2NF.
    • 3NF: in 2NF with no transitive dependencies: “the key, the whole key and nothing but the key”. When A → B is removed into a new table, the determinant A stays behind as a foreign key.
  3. Data types and storage (Block 3)
    • CHAR(N) reserves a fixed amount of memory for every value (wasteful for short or variable text), whereas VARCHAR(N) stores only what is entered, up to N.
    • A data type fixes the allowed values, memory size, valid operations and interpretation, which prevents errors.
  4. Three-layer architecture and sequence diagrams (Blocks 3 and 4)
    • Boundary (:Form): user interaction, input and error display. Controller (:Handler): use case logic, validation and transactions. Entity (:Table): persisted records represented in memory.
    • Frames: alt (if–else), opt (only if a condition is true), loop (repetition) and ref (refers to another diagram).
    • Messages: a solid horizontal arrow is a synchronous call; a dashed arrow is a return value.
  5. ADO.NET, C# and usability (Block 4)
    • OleDbConnection (the channel to the .accdb file), OleDbCommand (SQL text and parameters; ? placeholders are filled strictly by position), OleDbDataReader (fast, read-only, forward-only, needs an open connection) and OleDbDataAdapter with a DataTable (disconnected data for grids).
    • ExecuteNonQuery() returns the number of rows affected (never a new primary key). ExecuteScalar() returns the first column of the first row, such as a COUNT(*). ExecuteReader() returns a stream of rows for a SELECT.
    • ComboBox: DisplayMember is the text the user sees (CourseName); ValueMember is the underlying foreign key (CourseCode).
    • Usability: Shneiderman’s 8 golden rules (consistency, informative feedback, error prevention) and Nielsen’s 10 heuristics (visibility of system status, recognition rather than recall).
Section B — Interaction Design, Usability & UI Scenario17 MARKS

A brief business scenario testing practical application of interface design rules · suggested time: about 35 minutes

  • Usability frameworks: apply Shneiderman’s 8 golden rules and Nielsen’s 10 heuristics to evaluate or redesign screens.
  • Form and control selection: justify ComboBox (DisplayMember versus ValueMember), TextBox, DateTimePicker and read-only labels.
  • Feedback and error handling: clear status indicators, action-oriented button verbs, inline validation markers (ErrorProvider).
Section C — Comprehensive Case Scenario68 MARKS

The largest section: integrated systems analysis, database design, sequence diagrams and reporting · suggested time: about 105 minutes

  1. Use case realisation with sequence diagrams (DSDs): three-layer lifelines (boundary → controller → entity); the frames alt, opt, loop and ref; the CRUD technique to derive method calls and parameters.
  2. Database design and ERDs: extract business rules; translate class diagrams into ERDs; place the 1-side PK in the many side as an FK; resolve many-to-many relationships with bridge tables.
  3. Elements of use case descriptions: pre-conditions, post-conditions and the main success scenario.
  4. ADO.NET and code analysis: predict the output of ExecuteNonQuery(), ExecuteScalar() and ExecuteReader(); parameter order with ? placeholders; handling OleDbException.
  5. Report design and wireframing: the 7-field report rationale table (name, type, format, recipients, frequency, rationale, decisions), a prototype with calculated / derived fields, and the supporting SQL.
